# 07: Freshness window and conditional requests

**What to build:** A stored Version whose age — counted from the later of its `fetched_at` and its last `checks.csv` row of any result — is under the freshness window is returned without a request. Older, `get` sends a conditional request (`If-None-Match` / `If-Modified-Since` from the latest Version's frontmatter) to `original.url` and records one of four outcomes in `checks.csv` (`url, checked_at, result, status, sha256`): `304`, or `200` with the same received bytes, or `200` with different bytes but the same Markdown after conversion by the Version's step → `unchanged`, latest Version returned; different bytes and different Markdown → `changed`, a new Version beside the old, new path returned; `404`/`410` → `gone`, a warning, latest Version returned; a `200` whose media type fails the Version's step (a Twin address answering HTML) → `error` with status `200`, nothing stored; any other status, `403` and `429` included (the browser is never used for a comparison) → `error` with that status code; a transport exception → `error` with the exception's class name; both with a warning and the latest Version returned. Without any stored Version, `gone` and `error` exit non-zero. The window is `freshness_days` from `lorekeep.toml`, overridden per call by `--max-age <days>`; `--fresh` means `--max-age 0`. A Version whose `converter` says `via crawl4ai` is never rechecked by `get`: it is returned with a warning and `outcome: skipped`. The `checks.csv` append goes through the commit point. Old Versions in tests come from a real `get` aged by ticket 01's helper.

## Comments

2026-10-17 — Decisions made while building this ticket. (1) The Recheck lives in `lorekeep.recheck`, which ticket 09 reuses: `perform(store, stored, client, rules, tags=)` sends the conditional request to `original.url`, judges the answer and makes one commit (the `checks.csv` row, any new Version, the Tag rows it was handed); `is_fresh(stored, checks, window_days)` counts the age from the later of `fetched_at` and the last row; `skipped_reason(stored)` names why an `owner:` Source or a `via crawl4ai` Version is never asked — `get` treats both as `skipped`, since an owner's Source has no publisher either. (2) The Twin step and the page step expose their response parsing (`cascade.twin.read_twin`, `cascade.page.convert_response`) so a Recheck converts with the Version's step: a Version with `converter: md-twin` is gated by the Twin's media-type rule under the host's current rule (`text/markdown` is accepted even when the rule no longer names a Twin), any other web Version by the media types of its own step (revised 2026-10-17, review fix A5: an HTML Version whose address answers a PDF is an `error` with status `200`, never a PDF Version); a conversion that fails after the gate (no content, not a PDF) is an `error` with status `200` too. (3) A changed page is stored under the Source's stored `url`, not under whatever canonical address the new response names: the Recheck asks that Source, and a renamed page is for a `get --fresh` of the new address. (4) The lookup breaks a tie on `checked_at` in favour of the later row in the file, so three `get --max-age 0` within one second (A, changed, A) leave A current; two Rechecks of one Source with the same answer in the same second were one row under ticket 02's first reading; revised 2026-10-17 (review fix A7, spec story 34): every Recheck is appended whatever the answer, so the concurrency test asserts one header and six rows. (5) `provenance.build` and `now` moved from `commands/get.py` and `commands/add.py` to `lorekeep.provenance`, since the Recheck builds a Version's frontmatter too. (6) Warnings are `lorekeep: warning: <address> is gone (404); returning the stored Version` and the like, on stderr in every mode.
