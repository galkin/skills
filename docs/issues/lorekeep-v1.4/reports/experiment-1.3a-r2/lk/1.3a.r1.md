## 1.3.1 fm-input-quality-gates — score 10/10

Checked facts:
- A blank CSV value in a String column becomes an empty string and passes `Completeness`; in an Int column it becomes NULL and fails — https://docs.aws.amazon.com/glue/latest/dg/dqdl-rule-types-Completeness.html — ok
- `IsComplete` checks 100% completeness; `RowCountMatch`, `SchemaMatch`, `DatasetMatch` and `ReferentialIntegrity` compare against a reference dataset — https://docs.aws.amazon.com/glue/latest/dg/dqdl-rule-types.html — ok
- DQDL does not support nested or list-type column data — https://docs.aws.amazon.com/glue/latest/dg/dqdl-rule-types.html — ok (the page says "doesn't currently support"; dropping "currently" is the right timeless wording)
- `CountTokens` takes `modelId` and returns `inputTokens`, and its input must be compatible with the model — https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_CountTokens.html — ok

Findings:
- [S1] should-fix — 1-3-1-fm-input-quality-gates.md:28 — "Define how your application treats whitespace and placeholder strings before measuring them" leaves the check abstract, but DQDL has a documented mechanism for it: the `EMPTY` keyword "resolves to true for an empty string ("") value in a string column", and `WHITESPACES_ONLY` matches values that are only whitespace. Both work inside `ColumnValues` value lists, as in the page's example `ColumnValues "colA" not in ["a", "b", WHITESPACES_ONLY]`. Name both keywords as the content check that closes the empty-string gap in `Completeness`. Note that an `or` composite of them, such as `(ColumnValues "colA" = EMPTY) or …`, needs `compositeRuleEvaluation.method` = `ROW`. Cite AWS, [Data Quality Definition Language reference](https://docs.aws.amazon.com/glue/latest/dg/dqdl.html), section "Keywords for NULL, EMPTY and WHITESPACES_ONLY". The scenario at line 65 ("text-content checks") can then name the rule.
