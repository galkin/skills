# 02: The Store, its commit point, and `add`

**What to build:** The Store module that every later command writes through, proven with the one command that needs no network. `add <file> --title <t>` copies a Markdown or text file into the Store as a Version `owner--<slug>--<sha8>.md` with `url: owner:<slug>`, `origin: owner`, `authority: generated` (or `--authority`), `publisher` from `--publisher` (default `owner`), `converter: owner`, `fetched_at` from the file's mtime or `--fetched-at`, and the Run's Tag. Underneath: URL normalisation as the spec lists it, including reducing a Twin URL to its page URL under a host rule; the two-layer host table lookup by longest prefix with the unknown-host warning; the Version file name with its 200-byte cut and the stem rule (stem = file name without `.md`, hash included); the lookup of the latest Version for a URL without an Index (read every file's frontmatter, match `url` and `requested`, newest `fetched_at` wins) and through the Index when ticket 08 provides one; and one commit function with the spec's full signature — optional Version with optional Original bytes, `tags.csv` rows, `checks.csv` rows, any of them empty — that takes `.lorekeep.lock`, writes files to `<name>.tmp-<pid>` then renames (an existing target is left alone), appends the rows, calls an Index notification that is a no-op until ticket 08, and releases the lock. Later tickets call it with different arguments and never widen it. A test helper writes a Version from a fixture folder (body converted or copied, `original.sha256` of that response's bytes, `original.url` its URL) with a chosen `fetched_at`, for every later ticket that needs a stored Version.
