# Many workers write one Store at once

A Run has several workers (six in the first Project), each calling lorekeep against the same Store
from its own worktree. So: a Version and its Original are written to a temporary file and renamed
into place, and the name is the content hash, so two workers fetching one page produce one file
and the second rename is harmless; `tags.csv` and `checks.csv` are appended under a file lock;
`sources.db` runs in WAL mode so readers never wait for a writer, and a reader takes the lock only
to rebuild the Index, never to query it; `datapackage.json` is regenerated by `backup` under the
same lock. The lock is not re-entrant: it is taken inside a commit and inside a rebuild and never
nested.

The previous tool had a lock around its index and still produced duplicate pages under two names,
because the name was chosen by the worker; naming by hash removes the race rather than guarding it.

Where a page comes from decides what it is worth, so `lorekeep.toml` holds a table of
`host[/path prefix] → publisher, authority` (`raw.githubusercontent.com/anthropics` is primary,
the rest of GitHub is not). An unknown host is recorded as `third-party` and `get` prints a warning,
so the owner extends the table rather than an agent guessing; the safer of the two wrong defaults
is the one that stops a fact from being cited.
